# КОЗЫРЬ

Покер и дурак по сети прямо в браузере. Без регистрации, установки и сервера приложений.

Комната создаётся по трёхзначному коду, игроки заходят по нему же или по ссылке.
До шести человек за столом, можно добавить ботов и вмешаться ходом через админ-панель.

---

## Что нужно, чтобы запустить

```bash
npm install
npm run serve
```

Сервер поднимется на порту 9000 и напечатает две ссылки:

```
Для себя:     http://localhost:9000
Для игроков:  http://192.168.0.15:9000
```

Свою ссылку «Для игроков» отправьте остальным — они входят по коду.

Сервер делает две вещи: отдаёт собранную игру и поднимает сервер сигнализации
для WebRTC. Сам игровой трафик идёт напрямую между браузерами, сервер в нём
не участвует.

Если папка `dist/` пуста, сервер об этом скажет при запуске. Соберите заранее:

```bash
npm run build
```

## Три способа играть вместе

| Способ | Кто может играть | Что нужно |
|---|---|---|
| **Быстрая игра** | вы один, против ботов | ничего |
| **В этом браузере** | вкладки одного браузера или одного компьютера | ничего, работает без интернета |
| **Через интернет** | разные устройства и люди | сервер сигнализации |

### «В этом браузере»

Откройте игру в нескольких вкладках и создайте комнату в одной, войдите по коду
в остальных. Вкладки увидят друг друга напрямую через `BroadcastChannel`,
сервер не нужен вообще. Удобно проверять игру и играть с соседями за одним компьютером.

### «Через интернет»

Нужен сервер сигнализации — он знакомит браузеры между собой, а дальше они
говорят напрямую.

**Свой сервер.** `npm run serve` поднимает его на том же порту, что и игру.
Раздайте этот адрес друзьям — и они увидят и игру, и сигнализацию.

**Публичный сервер PeerJS.** Если ничего не настраивали, игра использует
`0.peerjs.com`. Он бесплатный и работает сразу, но это чужая машина: через неё
проходят коды комнат, и она может быть недоступна. Интерфейс честно
предупреждает об этом. Для постоянной игры поднимите свой.

**Свой сервер в интернете.** Подойдёт любой бесплатный хостинг с Node.js
(Render, Railway, Fly.io). Нужен `PORT` из окружения — сервер берёт его сам,
по умолчанию 9000. Сайт на Pages при этом остаётся статическим.

## Разработка

```bash
npm run dev        # разработка на :3000
npm run serve      # продакшн-сборка на :9000, раздаёт dist/
```

Если хотите отлаживать с сервером сигнализации на своём же порту:

```bash
npm run serve      # в одном окне
DEV_PROXY=1 npm run serve   # во втором — вместо dist/ отдаёт Vite с :3000
```

### Проверки

```bash
npm run typecheck  # ошибки типов
npm test           # игровая логика
npm run build      # типы + сборка
```

Тесты проверяют движок покера: оценку комбинаций, раздачу карт, поведение
при олл-ине и то, что фишки не появляются из ниоткуда. Ошибка в этой части
незаметна глазами — она просто отдаёт банк не тому, поэтому ломает сборку.

## Как устроено

Хост держит игру и рассылает каждому игроку персональное состояние. Гости
присылают только свои действия. Это избавляет от синхронизации игровой логики
между узлами: расклад вычисляет только хост.

```
src/
  lib/
    types.ts      модель данных: представления, сообщения, команды
    cards.ts      колода, сортировка, старшинство карт
    poker.ts      движок покера
    durak.ts      движок дурака
    host.ts       оркестратор комнаты: места, боты, рассылка состояний
    net.ts        мост между host.ts и транспортом
    sound.ts      звуки на WebAudio, без файлов
  net/
    types.ts      контракт транспорта
    local.ts      вкладки одного браузера (BroadcastChannel)
    webrtc.ts     разные устройства (PeerJS)
  screens/        главная, комната, лобби, столы
  components/     карты, иконки, чат, админ-панель
server.mjs        раздача игры + сервер сигнализации
```

Транспорт подменяется в одном месте. Чтобы связи работают одинаково, хост
и гость должны выбрать один и тот же режим.
